# mcc-check

**MCC का संकेत, MDR का हिसाब और merchant audit।**

> **स्थिति: प्रारंभिक प्रोटोटाइप।** MCC सूची अभी पूरी तरह आधिकारिक सूची से मिलाई नहीं गई है, और MDR दरें समाचार रिपोर्टों पर आधारित हैं। उपयोग से पहले नीचे "यह tool क्या नहीं करता" और "डेटा की सीमा" पढ़ें।

## Demo (ब्राउज़र में, बिना इंस्टॉल)

- **लाइव demo:** GitHub Pages पर `docs/index.html` (सेटअप के बाद यह लिंक खुलेगा)।
- **या अपनी मशीन पर:** `web/index.html` फ़ाइल को Chrome में डबल-क्लिक करके खोलें।

Demo में MCC खोज, नियम-आधारित MCC सहायक, MDR हिसाब और statement जाँच काम करते हैं। AI सहायक वैकल्पिक है। उसे चालू करने के लिए पहले सहमति दें और अपनी API key डालें। Key केवल उस ब्राउज़र टैब में रहती है, कहीं सेव नहीं होती। Hosted पेज पर बाहरी API calls ब्लॉक हो सकती हैं, इसलिए AI के लिए फ़ाइल को अपनी मशीन पर खोलें।

MCC (मर्चेंट कैटेगरी कोड) एक 4-अंकों का कोड है। यह तय करता है कि merchant से कितना शुल्क (MDR) लिया जाएगा। यह कोड merchant खुद नहीं चुनता, इसे acquirer या payment processor तय करता है। गलत MCC से merchant का सीधा नुकसान हो सकता है, इसलिए यह tool तीन काम करता है:

1. **लुकअप:** किसी MCC कोड का अर्थ देखें।
2. **संकेत:** merchant के नाम या narration से संभावित MCC सुझाएँ।
3. **Audit:** statement की जाँच करें कि कटा MDR नियम के अनुसार सही है या नहीं, और MCC की समीक्षा की ज़रूरत है या नहीं।

सब कुछ आपकी मशीन पर चलता है। इसमें कोई network call नहीं है और कोई बाहरी dependency नहीं है।

## शुरू करें

Python 3.9 या नया चाहिए।

```
python3 -m mcc_check lookup 5912
python3 -m mcc_check suggest "गुप्ता मेडिकल हॉल"
python3 -m mcc_check mdr --amount 5000 --instrument upi_p2m
python3 -m mcc_check audit examples/statement.csv --dispute
```

Tests चलाने के लिए:

```
python3 -m unittest discover -s tests -t .
node tests/web/test_web_logic.js
```

दूसरी लाइन ब्राउज़र के logic की जाँच करती है (Node 18+ चाहिए)। इसमें AI का mock fetch भी है, असली API कॉल नहीं होती।

## Statement फ़ाइल का फ़ॉर्मैट

CSV में ये कॉलम होने चाहिए:

| कॉलम | ज़रूरी | अर्थ |
|---|---|---|
| `date` | हाँ | `YYYY-MM-DD` |
| `amount` | हाँ | लेनदेन की रकम |
| `mdr_charged` | हाँ | जो MDR कटा |
| `merchant_name` | हाँ | merchant का नाम |
| `assigned_mcc` | हाँ | जो MCC assign हुआ |
| `instrument` | नहीं | जैसे `upi_p2m`, डिफ़ॉल्ट यही है |

## नियम कैसे बदलें

डिफ़ॉल्ट नियम एक बैंक की सूचना पर आधारित हैं, जिसमें सामान्य UPI P2M पर 0.40% तक शुल्क है, अधिकतम ₹300 प्रति लेनदेन, और ₹2,000 तक शून्य। नियम बदलने पर JSON फ़ाइल दें:

```json
{
  "upi_p2m": {"rate": "0.004", "cap": "300", "zero_below": "2000"},
  "rupay_cc_upi:5541": {"rate": "0.01", "cap": null, "zero_below": "0"}
}
```

`instrument:MCC` वाली कुंजी किसी खास MCC के लिए नियम देती है। इसे `--rules` से पास करें।

## यह tool क्या नहीं करता

- यह MCC नहीं बदलता, और merchant को MDR बचाने के लिए category बदलने की सलाह नहीं देता। MCC की अंतिम पुष्टि acquirer या payment service provider करता है।
- यह किसी बैंक या NPCI से जुड़ा नहीं है।
- यह कानूनी या वित्तीय सलाह नहीं है।
- MDR की दरें बैंक के अनुसार अलग हो सकती हैं, और नियम समय के साथ बदलते हैं। हर दर का स्रोत और तारीख जाँचें।

## Dispute draft

`--dispute` से हर OVERCHARGE और MCC_REVIEW मामले के लिए acquirer या NPCI को भेजने योग्य समीक्षा-अनुरोध का मसौदा मिलता है। यह केवल समीक्षा माँगता है, और अंतिम निर्णय acquirer या NPCI का होता है।

## डेटा की सीमा

- **MCC सूची अधूरी है।** यह ISO 18245 का 32 कोड का प्रारंभिक उपसमुच्चय है, जिसमें भारतीय keywords जोड़े गए हैं। ज़्यादातर कोड NPCI की RuPay सूची से मेल खाते हैं। **0742, 3020, 8099, 8398** की पुष्टि अभी नहीं हुई है।
- **MDR दरें पुष्ट नहीं हैं।** नियम समाचार रिपोर्टों (सितंबर-अक्टूबर 2026) पर आधारित हैं। NPCI के मूल दस्तावेज़ से मिलान बाकी है। लागू होने की तारीख भी टाली गई थी, इसलिए NPCI की ताज़ा सूचना देखें। सभी merchant श्रेणियों के लिए एक दर मानी गई है।
- **AI सुझाव केवल संकेत हैं।** असली Gemini और Anthropic कॉल की जाँच अभी नहीं हुई है।
- **Keyword मिलान गलत भी हो सकता है।** छोटे शब्द (जैसे "कर") कई नामों में मिल सकते हैं।

योगदान का स्वागत है, पर असली merchant या bank का डेटा commit न करें।

## सुरक्षा और गोपनीयता

- Demo में कोई डेटा सर्वर पर नहीं जाता, सिवाय उस AI सेवा के जिसे आप खुद चुनें और जिसकी सहमति दें।
- AI को केवल कारोबार का विवरण जाता है, और वह भी भेजने से पहले फ़ोन नंबर, ईमेल और लंबी संख्याएँ हटाकर।
- बैंक, खाता या लेनदेन का डेटा कभी नहीं भेजा जाता।
- Production में API key browser में नहीं रखनी चाहिए। उसके लिए backend proxy लगाएँ।
